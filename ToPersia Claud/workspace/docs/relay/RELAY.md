## گردش کار

### الف. موازی — پیش‌فرض (OPS-D005)

1. در جدول lane پروندهٔ `CURRENT.md` دو مسیر جدا بنویس؛ مثلاً ابری: `workspace/plugin/topersia-schema/` · محلی: `workspace/plugin/topersia-render/`.
2. جلسه را از claude.ai/code روی `main` باز کن و در دستورش مسیر خودش (lane) را صریح بگو؛ `to-cloud` را اجرا نکن — همهٔ تغییرهای پیگیری‌شدهٔ نیمه‌کاره را برمی‌دارد و شاخهٔ محلی را عوض می‌کند (OPS-D009). جلسهٔ ابری شاخهٔ خودش (`claude/…`) را push می‌کند.
3. هم‌زمان کار محلی روی lane خودش ادامه دارد.
4. پایان کار ابری ← `from-cloud` ← بازبینی و گیت‌های محلی ← `--squash` ← commit دسته‌ای.

### ب. سهمیهٔ محلی تمام شد

عامل محلی جواب نمی‌دهد؛ خودت در PowerShell:

```powershell
cd C:\wamp64\www\topersia
& C:\wamp64\bin\php\php8.3.28\php.exe "ToPersia Claud\workspace\scripts\relay\tp-relay.php" to-cloud --wip
```

`--wip` لازم است چون درخت کار نیمه‌کاره است؛ بی آن `to-cloud` کد ۲ می‌دهد. بی `--task`، دستور جلسه «ادامهٔ قدم بعدی بخش محلی» است — همان که عامل محلی در `CURRENT.md` به‌روز نگه داشته. اگر `claude` در PATH نیست: `--no-launch` و جلسه را از claude.ai/code روی شاخهٔ `relay/…` باز کن.

### ج. برگشت — اعتبار تمام شد یا سهمیه ریست شد

```powershell
& C:\wamp64\bin\php\php8.3.28\php.exe "ToPersia Claud\workspace\scripts\relay\tp-relay.php" from-cloud
& C:\wamp64\bin\php\php8.3.28\php.exe "ToPersia Claud\workspace\scripts\relay\tp-relay.php" from-cloud claude/<شاخه> --gates
```

سپس آزمون‌های «در انتظار تأیید محلی» را عامل محلی اجرا می‌کند و در پایان `--gates --squash`. برای ادامهٔ **همان گفت‌وگو** در ترمینال: `claude --teleport` (درخت کار باید تمیز باشد).

## پرونده‌های رله و ادغام بی‌تداخل

| پرونده | نویسنده | ادغام |
|---|---|---|
| `CURRENT.md` | بخش محلی ← فقط عامل محلی · بخش ابری ← فقط جلسهٔ ابری (دستورش را `to-cloud` می‌نویسد) · جدول lane ← فقط محلی | بخش‌ها از هم دورند، پس git خودش ادغام می‌کند |
| `HISTORY.md` | `to-cloud` و `from-cloud` — یک سطر هر تحویل | فقط افزودنی؛ `merge=union` |
| `GATES.md` | `gates --record` و `from-cloud --squash` | فقط افزودنی؛ `merge=union` |

در آزمون پایان‌به‌پایان (دو lane هم‌زمان، هر دو طرف CURRENT.md و GATES.md را نوشتند) ادغام squash بی هیچ تداخل انجام شد.

## فرمان‌ها

| فرمان | کار |
|---|---|
| `status [--fetch]` | شاخه، جلو/عقب، شاخه‌های رله و ابری، آخرین تحویل و گیت |
| `preflight` | نام‌های قابل‌حمل و پروندهٔ حساس پیگیری‌شده |
| `to-cloud [--task=… \| --task-file=…] [--all] [--no-launch] [--dry-run]` | WIP ← `relay/YYYYMMDD-HHMM` ← push ← `claude --cloud` |
| `from-cloud [شاخه] [--gates] [--squash]` | فهرست، بازبینی روی `review/…`، گزارش هم‌پوشانی، ادغام squash (staged) |
| `gates [--record]` | گیت‌های همین محیط؛ `--record` یک سطر در `GATES.md` |
| `session-start [--force]` | قلاب آغاز جلسهٔ ابری: `TP_ENV` ابری و قواعد حالت ابری |

پروندهٔ تازهٔ بیرون از `workspace/` با `to-cloud` اضافه نمی‌شود مگر `--all` — تا عکس و آپلود و پروندهٔ موقت به شاخه نروند. گارد پیش از commit پروژه (`scripts/git-guard`) روی commit رله هم اجرا می‌شود.

## راه‌اندازی یک‌باره

1. نصب اپ Claude روی `abashash/ToPersia` (فقط همین مخزن) — github.com/apps/claude.
2. `claude auth login` با حساب claude.ai (نه کلید API).
3. محیط ابری پیش‌فرض (Default، شبکهٔ Trusted) کافی است؛ متغیر محیطی لازم نیست — قلاب، `TP_ENV` را خودش می‌سازد.
4. پیش از اولین جلسه، preflight باید سبز باشد (OPS-D006).
