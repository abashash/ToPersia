# ToPersia — مرجع فنی ساختار فایل Export جت‌انجین

**نسخه:** ۱.۰ · **تاریخ:** ۲۷ اوت ۲۰۲۶ · **مبنا:** JetEngine 3.8.13.2 · **روش:** تحلیل برنامه‌ای فایل export واقعی نصب زنده

> این سند از **خواندن مستقیم فایل export** به دست آمده، نه از مستندات یا حدس. هر ادعایش با تحلیل برنامه‌ای روی نصب واقعی ToPersia راستی‌آزمایی شده.

---

## بخش ۱ — چرا این سند وجود دارد

تا پیش از این، هر موجودیت تازه به‌صورت **جدول دستی** تحویل می‌شد و مالک پروژه فیلدها را یکی‌یکی در پنل می‌ساخت. ساخت P1 نشان داد این روش شکننده است: ۳۶ زیرفیلد به‌جای داخل Repeater، در سطح‌بالا ساخته شدند و خطا تا مرحلهٔ رندر صفحه کشف نشد.

تصمیم `P5-D101` این روش را کنار گذاشت. از این پس تحویل به‌صورت **فایل JSON آمادهٔ Import** انجام می‌شود. این سند ساختار آن فایل را مستند می‌کند.

---

## بخش ۲ — ساختار سطح‌بالا

فایل export یک شیء JSON با ده کلید ثابت است:

| کلید | نوع | توضیح |
|------|-----|--------|
| `post_types` | list | هر عضو یک پست‌تایپ |
| `taxonomies` | list | در ToPersia همیشه خالی |
| `listings` | list | Listing Grid ها |
| `components` | list | — |
| `meta_boxes` | **dict** | کلید = `meta-N` |
| `relations` | list | روابط |
| `options_pages` | list | — |
| `glossaries` | list | واژه‌نامه‌ها |
| `queries` | list | Query Builder |
| `content` | null | — |

**نکتهٔ کلیدی:** `meta_boxes` تنها بخشی است که `dict` است، نه `list`. برای import انتخابی، فقط همان کلید مورد نظر را نگه دار و بقیهٔ کلیدها را خالی بگذار:

- `post_types` → `[]`
- `meta_boxes` → `{"meta-36": {...}}`
- `content` → `null`

این کار تضمین می‌کند import چیز دیگری را لمس نکند.

---

## بخش ۳ — متاباکس

### ۳.۱ ساختار

هر عضو `meta_boxes` سه کلید دارد: `args` · `meta_fields` · `id`

**`args` یک dict معمولی است** (نه سریال‌شده) با این کلیدها:

`object_type` · `allowed_tax` · `allowed_post_type` · `allowed_posts` · `excluded_posts` · `active_conditions` · `position` · `priority` · `name`

`allowed_post_type` یک list از slug های پست‌تایپ است — همان چیزی که در UI با عنوان **Enable For Post Types** دیده می‌شود.

### ۳.۲ فیلد سطح‌بالا

هر عضو `meta_fields` این کلیدها را دارد:

| کلید | همیشه؟ | توضیح |
|------|--------|--------|
| `title` | بله | برچسب فارسی |
| `name` | بله | متاکلید |
| `type` | بله | `text` · `textarea` · `wysiwyg` · `number` · `switcher` · `select` · `checkbox` · `date` · `media` · `gallery` · `repeater` |
| `id` | بله | عدد یکتا |
| `options_source` | بله | `manual` یا `glossary` |
| `description` | معمولاً | توضیح فارسی |
| `width` | معمولاً | `100` · `50` · `33.33` |
| `required` | اختیاری | بولین |
| `is_rest` | اختیاری | بولین |
| `glossary_id` | فقط glossary | **رشته**، نه عدد — مثل `"179"` |
| `options` | فقط select/checkbox | آرایه، برای glossary خالی |
| `min_value` · `step_value` | فقط number | رشته |
| `repeater-fields` | **فقط repeater** | آرایهٔ زیرفیلدها |

### ۳.۳ زیرفیلد Repeater — مهم‌ترین بخش

زیرفیلدها **داخل** `repeater-fields` والدشان می‌نشینند، نه در `meta_fields`.

مجموعهٔ کلیدهای زیرفیلد **کوچک‌تر** است:

| کلید | توضیح |
|------|--------|
| `title` | برچسب |
| `name` | نام زیرفیلد |
| `type` | نوع |
| `id` | عدد یکتا |
| `options_source` | `manual` یا `glossary` |
| `options` | فقط برای glossary — آرایهٔ خالی |
| `glossary_id` | فقط برای glossary |
| `min_value` · `step_value` | فقط number |

**این کلیدها در زیرفیلد وجود ندارند:** `required` · `width` · `is_rest` · `description` · `conditional_logic`

پنل جت‌انجین هم فقط همین‌ها را نشان می‌دهد: Label · Name · Type · Source · Glossary · Placeholder · Multiple

**پیامد برای بسته‌های ساخت:** هرگز برای زیرفیلد ستون «الزامی» یا «عرض» ننویس. وجود ندارند (`P5-D100`).

### ۳.۴ 🔴 شمارندهٔ Meta fields

جت‌انجین در فهرست متاباکس فقط **فیلدهای سطح‌بالا** را می‌شمارد. زیرفیلدهای Repeater در شمارش نمی‌آیند.

| حالت | شمارنده |
|------|----------|
| ساخت درست: ۲۸ فیلد + ۳۶ زیرفیلد | **۲۸** |
| ساخت غلط: ۶۴ فیلد تخت | **۶۴** |

**هر بستهٔ ساخت باید عدد مورد انتظار را صریح بنویسد** (`P5-D099`). این تنها راهی است که ساخت تخت به‌جای تودرتو در ثانیهٔ اول کشف می‌شود.

---

## بخش ۴ — پست‌تایپ

برخلاف متاباکس، `args` و `labels` در پست‌تایپ **رشتهٔ سریال‌شدهٔ PHP** هستند، نه dict.

| کلید | نوع |
|------|-----|
| `slug` | رشتهٔ ساده — مثل `tp_visa` |
| `args` | رشتهٔ سریال‌شدهٔ PHP |
| `labels` | رشتهٔ سریال‌شدهٔ PHP |
| `meta_fields` | معمولاً خالی |
| `id` | عدد |

برای خواندن در پایتون: `phpserialize.loads(s.encode('utf-8'), decode_strings=True)`

کلیدهای مهم داخل `args`: `rewrite_slug` · `has_archive` · `hierarchical` · `menu_icon` · `show_in_rest` · `supports` · `capability_type` · `public` · `publicly_queryable`

---

## بخش ۵ — رابطه

### 🔴 نام رابطه کجاست

| کلید | محتوا |
|------|--------|
| `slug` | **همیشه خالی** |
| `args['name']` | **همیشه خالی** |
| `labels['name']` | ✅ **نام واقعی رابطه اینجاست** |

این نکته یک بار در ممیزی باعث خطای جدی شد: چون نام‌ها خوانده نشدند، ده رابطهٔ مشروع اشتباهاً «تکراری» تشخیص داده شدند. تصمیم `P5-D102` از همین‌جا آمد: هر ادعای تکراری‌بودن فقط پس از خواندن نام واقعی مجاز است.

### کلیدهای `args` (سریال‌شده)

`parent_object` و `child_object` با پیشوند `posts::` می‌آیند — مثل `posts::tp_country`

`type` یکی از: `many_to_many` · `one_to_many` · `one_to_one`

سایر کلیدها: `parent_control` · `child_control` · `parent_rel` · `child_rel` · `db_table` · `parent_rest` · `child_rest`

### کلیدهای `labels` (سریال‌شده)

`name` · `parent_page_control_title` · `parent_page_control_connect` · `parent_page_control_select` · `child_page_control_title` · `child_page_control_connect` · `child_page_control_select`

---

## بخش ۶ — واژه‌نامه

| کلید | توضیح |
|------|--------|
| `id` | عدد |
| `name` | نام واژه‌نامه |
| `source` | `manual` یا `file` |
| `fields` | آرایهٔ آیتم‌ها |

هر آیتم: `value` · `label` · `is_checked`

**قاعدهٔ `P5-D040`:** `source` همیشه باید `manual` باشد. اگر `file` باشد، برچسب‌ها در دیتابیس ثبت نمی‌شوند و WPML String Translation آن‌ها را نمی‌بیند.

**راه ورود انبوه بدون نقض قاعده:** فایل CSV آپلود کن → `Get items from uploaded file` → ستون‌ها را تعیین کن → Save → دکمهٔ **Convert to Manual Source** → **Save دوباره**. نتیجه با تایپ دستی یکسان است.

قالب CSV: دو ستون `value` و `label` · UTF-8 **بدون BOM** (BOM نام ستون اول را خراب می‌کند) · نام ستون‌ها حساس به حروف بزرگ و کوچک.

## بخش ۷ — رفتار Import

| رفتار | جزئیات |
|--------|---------|
| شناسهٔ متاباکس | ممکن است **عوض شود** — `meta-36` وارد شد و `meta-37` ساخته شد |
| متاباکس قدیمی | **خودکار حذف نمی‌شود** — باید دستی پاک شود |
| ریسک | دو متاباکس فعال روی یک نوع پست با متاکلیدهای یکسان، **رندر Repeater را می‌شکند** بدون آسیب به داده (`P5-D107`) |

### روال امن import

| گام | اقدام |
|-----|--------|
| ۱ | بکاپ Duplicator |
| ۲ | Import فایل |
| ۳ | فهرست Meta Boxes را باز کن — اگر دو متاباکس هم‌نام دیدی، **آن‌که شمارندهٔ غلط دارد** را حذف کن |
| ۴ | عدد `Meta fields` را با سند مطابقت بده |
| ۵ | صفحهٔ ویرایش یک رکورد را باز کن — زیر هر Repeater فقط `+ ADD ITEM` باشد، هیچ فیلد بازی بیرون جعبه نباشد |

## بخش ۸ — تنظیماتی که در فایل export دیده نمی‌شوند

دو تنظیم Repeater در ساختار export ظاهر نشدند و باید **دستی** در پنل تنظیم شوند:

| تنظیم | محل در UI | مقدار توصیه‌شده |
|--------|------------|------------------|
| `Collapsed` | زیر کادر زیرفیلدها | **On** — برای Repeater با بیش از ده ردیف الزامی |
| `Title Field` | زیر `Collapsed` | زیرفیلد کلیدی — مثلاً `pc_country` |

**`Title Field` روی زیرفیلد Select کار می‌کند و برچسب واژه‌نامه را نشان می‌دهد، نه مقدار خام.** یعنی «آندورا» نه `ad`. این برای هر Repeater بزرگ ضروری است، وگرنه ردیف‌ها بی‌نام می‌مانند.

## بخش ۹ — ساختار ذخیره‌سازی در زمان اجرا

این بخش دربارهٔ فایل export نیست، بلکه دربارهٔ شکل دادهٔ Repeater در `wp_postmeta` است — لازم برای لایهٔ رندر و موتور JSON-LD.

### کلید آرایه

رشته با پیشوند `item-`: `item-0` · `item-1` · … `item-N`

### 🔴 همهٔ مقادیر رشته‌اند

| نوع فیلد | مقدار ذخیره‌شده |
|-----------|------------------|
| Number | `'14'` — نه `14` |
| Switcher | `'true'` یا `'false'` — نه بولین، نه `'1'`/`'0'` |
| Date | `'2026-01-01'` — قالب ISO |
| Select با واژه‌نامه | مقدار، نه برچسب: `'ad'` |
| Textarea خالی | `''` |

**تلهٔ رایج:** `if ($row['pc_voa_eligible'])` همیشه true برمی‌گرداند، چون `'false'` یک رشتهٔ ناتهی است. مقایسه باید `'true' === $row['pc_voa_eligible']` باشد.

### چک‌باکس چندمقداری

آرایهٔ تودرتو که **همهٔ گزینه‌ها** را نگه می‌دارد، نه فقط تیک‌خورده‌ها:

- `embassy` → `'true'`
- `e_visa` → `'false'`
- `voa` → `'false'`

پس نمی‌شود روی آن حلقه زد؛ باید فیلتر شود، وگرنه گزینه‌های تیک‌نخورده هم منتشر می‌شوند (`P5-D106`).

## بخش ۱۰ — چک‌لیست ساخت فایل import

| # | بررسی |
|---|--------|
| ۱ | فقط `meta_boxes` پر است؛ بقیهٔ کلیدها خالی |
| ۲ | تعداد `meta_fields` = عدد اعلام‌شده در بستهٔ ساخت |
| ۳ | هر Repeater آرایهٔ `repeater-fields` ناتهی دارد |
| ۴ | هیچ زیرفیلدی در `meta_fields` سطح‌بالا نمانده |
| ۵ | زیرفیلدها فقط کلیدهای مجاز بخش ۳.۳ را دارند |
| ۶ | `glossary_id` رشته است، نه عدد |
| ۷ | هر فیلد سطح‌بالا `description` فارسی دارد |
| ۸ | `args` و `id` متاباکس دست‌نخورده مانده‌اند |
| ۹ | هیچ نام یا نوع فیلدی نسبت به نسخهٔ مبدأ عوض نشده |

هر نُه مورد **برنامه‌ای** بررسی شود، نه چشمی.
