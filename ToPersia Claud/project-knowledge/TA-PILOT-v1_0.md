## ۱. P2-alpha — نتایج اجرای واقعی (2026-07-13، سندباکس معمار)

**محیط:** Node v22.22.2 · Astro 5 (نصب استاندارد npm) · سخت‌افزار کانتینر معمولی (بدون بهینه‌سازی).
**بار آزمون:** قالب واقع‌گرایانه per-page: breadcrumb + ۱۵ فیلد ساخت‌یافته + فهرست ۱۰ رابطه با صفتِ یال + ~۶۰۰ واژه متن + بلوک JSON-LD.

| آزمون | صفحات | زمان Build | توان |
|-------|--------|-------------|-------|
| نمونه | ۲٬۰۰۰ موجودیت × ۳ زبان = ۶٬۰۰۰ | ۱۱.۵ ثانیه | ~۵۲۲ صفحه/ثانیه |
| **مقیاس سقف** | **۲۱٬۶۰۰ موجودیت (عین سقف TA-VOL) × ۳ زبان = ۶۴٬۸۰۰** | **۸۹.۳ ثانیه** | ~۷۲۵ صفحه/ثانیه |

خروجی: ~۱٬۰۱۵ MB HTML · بارگذاری ۱۹۴ MB داده JSON در حافظه بدون مشکل · خطیّت مقیاس اثبات شد (توان در مقیاس بزرگ حتی بهتر شد — سربار راه‌اندازی مستهلک می‌شود).

**برون‌یابی سقف کامل (۹ زبان = ~۱۹۴٬۴۰۰ سند):** ~۴.۵ دقیقه رندر خالص. با ضریب بدبینانه ×۱۰ برای واقعیت تولید (fetch از API، رسانه، قالب غنی‌تر): **~۴۵ دقیقه** — همچنان کسر کوچکی از پنجره «بچ روزانه» NFR-OPS-01.

**حکم P2-alpha: PASS.** ریسک «گلوگاه Build در سقف» که ممیز حیاتی اعلام کرده بود، در لایه داده تجربتاً منتفی است. قیود صداقت: محتوای مصنوعی بود (بدون خط پردازش تصویر و بدون تأخیر API) — P2-beta پس از ساخت قالب واقعی، فقط برای تأیید ضریب واقعی، توصیه می‌شود اما مسدودکننده ۴.۷ نیست (مرتبه بزرگی مسئله بسته شد).

## ۲. پروتکل P0-HOST — تست کفایت هاست (۲ دقیقه، مستقل از P1-WP)

**پرسش فیصله‌دهنده:** آیا REST API وردپرس از بیرون (نه از داخل همان هاست) در دسترس است؟ این تنها نیمه پرریسک هشدار ممیز است؛ Webhook خروجی معمولاً محدود نمی‌شود.

**سریع‌ترین مسیر:** آدرس دامنه را بدهید، همین الان با `web_fetch` مسیر `/wp-json/` آن را از بیرون تست می‌کنم — دقیقاً همان زاویه‌ای که فرآیند Build آینده به آن نیاز دارد.

**یا خودتان در ۳۰ ثانیه:** از یک شبکه غیر از خودِ هاست (مثلاً اینترنت موبایل، نه وای‌فای همان دفتر/سرور) آدرس `https://دامنه‌شما/wp-json/` را در مرورگر باز کنید.
- ✅ **قبول:** یک پاسخ JSON با نام سایت و فهرست route ها دیده می‌شود.
- ❌ **رد:** ۴۰۳/۴۰۶، صفحه چالش امنیتی (Cloudflare/Wordfence)، یا timeout.

اگر رد شد: راه‌حل معمولاً یک تنظیم ساده در افزونه امنیتی (Whitelist مسیر `/wp-json/` یا IP سرویس Build) است، نه تغییر معماری — و حتی در بدترین حالت، VPS پشتیبان (~۱۰-۴۰$/ماه، از پیش در TA-AMENDMENT-001 محاسبه‌شده) شبکه ایمنی آماده دارد.

### نتیجه واقعی (۲۰۲۶-۰۷-۱۴)

**PASS.** `https://topersia.com/wp-json/` پاسخ کامل JSON داد (ده‌ها namespace فعال شامل `wp/v2` کامل). مسیر اولیه (`topersia.com/site/wp-json/`) به دلیل تفاوت `home` (ریشه دامنه) و `siteurl` (زیرپوشه `/site`) در تنظیمات وردپرس ۴۰۴ می‌داد — نه مسدودسازی امنیتی. **آدرس REST API برای پیکربندی Build آینده:** `https://topersia.com/wp-json/`. اولین گلوگاه زیرساختی معماری رسماً بسته شد.

## ۳. پروتکل P1 — آزمون ارگونومی UI (مجری: شما — ~۳۰–۴۵ دقیقه)

**پرسش فیصله‌دهنده:** آیا ویرایش «صفتِ زبان‌وابسته روی یال» در Studio برای یک ادیتور غیربرنامه‌نویس قابل‌تحمل است؟ (داده‌لایه‌اش قبلاً اثبات شد؛ اینجا فقط تجربه انسانی می‌ماند — و طبق تحلیل حساسیت ۴.۶، شکست اینجا = صعود Drupal به رتبه ۱.)

**گام‌ها:**
1. یک نمونه Directus بالا بیاورید — ساده‌ترین مسیر: trial ابری رایگان یا نصب Docker تک‌خطی روی VPS آزمایشی.
2. دو Collection بسازید: `events` و `places` (فقط فیلد name کافی است).
3. روی `events` یک فیلد **M2M** به `places` بسازید — Directus خودش Junction (`events_places`) می‌سازد.
4. وارد Collection جانکشن شوید (Settings → Data Model → نمایش Collectionهای مخفی) و یک فیلد `sequence_order` (Integer) اضافه کنید — این آزمون `sequence_order` روی R03 است.
5. روی همان جانکشن، یک فیلد **Translations** بسازید (ویزارد خودکار) و داخل Collection ترجمه‌اش فیلد `venue_name` (Text) اضافه کنید — این آزمون HF8 است.
6. یک event بسازید، دو place وصل کنید، برای هر اتصال `sequence_order` و `venue_name` را به **فارسی و انگلیسی** وارد کنید.
7. 🔬 **آزمون رگرسیون تاریخی:** فیلد Translations جانکشن را از Data Model باز و بدون تغییر ذخیره کنید؛ سپس رکوردها را چک کنید (issue قدیمی v9-rc: شکستن رابطه پس از Edit Field — باید ببینیم در نسخه فعلی مرده است).

**معیار قبول:** هر ۷ گام بدون کدنویسی و بدون گم‌شدن داده انجام شود **و** قضاوت شخصی شما: «ادیتور محتوای آینده‌ام می‌تواند روزی ده‌ها بار این کار را بکند بدون اینکه استعفا دهد.» نمره ۱–۵ بدهید؛ ≥۳ = PASS.

## ۴. پروتکل P3 — Flow هشدار Volatility (~۱۵ دقیقه)

در Settings → Flows: یک Flow با Trigger زمان‌بندی (Cron ماهانه) بسازید که آیتم‌های Collection آزمایشی با `last_verified_date` قدیمی‌تر از ۳۰ روز را بخواند و برایتان ایمیل/Notification بفرستد. **معیار قبول:** دریافت هشدار. (این عملاً بند ۳ سازوکار DP-402 است.)

## ۵. پروتکل P4 — مانور خروج (~۲۰ دقیقه)

از نمونه آزمایشی: (الف) Snapshot شِما بگیرید (`npx directus schema snapshot` یا از UI)، (ب) از دیتابیس dump بگیرید، (ج) روی یک نمونه تازه بازگردانی کنید، (د) شمارش ردیف‌ها را مقایسه کنید. **معیار قبول:** برابری کامل — این اثبات عملی HF5 و ماده اول Exit-Plan سند ۴.۷ است.
